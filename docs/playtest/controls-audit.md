# Controls audit

**Scope:** compare the visible controls and map gestures in OpenCoaster with the RCT2 park-management model, then verify that each enabled control responds. Audit runs use the desktop WebGL2 renderer and Playwright's Pixel 8 touch profile.

**Evidence:** the RCT2 manual is the primary reference for mouse construction and shortcuts: [RCT2 manual, pp. 9 and 14–29](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf). App behavior is checked against the live UI and source modules linked below. Touch long-press behavior is an OpenCoaster interaction; the RCT2 desktop manual does not define it.

## Map-object interaction inventory

The RCT2 manual's explicit right-click construction rule is removal of paths and scenery while using a construction tool. For long-press, expected behavior is the app's existing touch contract (select a meaningful object or show a refusal), since the desktop manual has no touch interaction.

**Evidence limits:** Playwright checks desktop path context-click status and scenery context-menu removal, serialized map mutation, empty-tile refusal, guest detail long-press, and path-removal long-press. The Starter Park ride-access E2E also right-clicks a coaster track tile while another construction tool is active and verifies that ride information opens; `e2e/context-menu.spec.ts` right-clicks prebuilt rides in Select mode and a patrol tile in Patrol mode. Staff, stall, terrain, and park-gate gestures are not individually hit-tested; those rows remain source-derived expectations, not claims of a live gesture test. Path handling remains in the owner scope `c49b7679`.

### Ride context-selection finding

The first full `pnpm e2e` run exposed a regression from this branch's scenery context-click routing: right-clicking a coaster track tile with a construction tool selected showed `No scenery on tile … to remove` instead of opening the ride information window. The existing Starter Park ride-access test reproduced it. The router now checks for a ride on the selected tile first and delegates that gesture to the existing forced-selection handler; ordinary scenery removal and empty-tile refusal remain intact. The focused failing test passes after the routing fix. This corrects object selection only; ride demolition behavior remains owned by run `425d8e5b`.

## Test contract

`e2e/control-contract.spec.ts` walks visible enabled controls in each opened toolbar window and active tab. It checks DOM values, tab/pressed state, visible windows/status, downloads, file import refusal, worker-visible state, map selection, or an explicitly selected state. The same toolbar/window sweep runs with desktop WebGL2 and Pixel 8 touch input. The file also checks keyboard actions, desktop path context-click, scenery removal/refusal, and existing mobile gesture coverage remains in `e2e/mobile-input.spec.ts`. Clear scenery and Water map behavior is covered by `e2e/area-tools.spec.ts`, and Select / Patrol right-click by `e2e/context-menu.spec.ts`.

The audit uses a deterministic starter scenario and the Sandbox for general window controls. Actions that depend on simulation ticks are resumed for the action, then paused again. This avoids treating a paused worker as evidence that an enabled command is broken.
