# RCT2 UI Fidelity Specification

## Scope and clean-room rules

This document specifies the player-facing park interface and input behavior of the original Windows release of _RollerCoaster Tycoon 2_ (RCT2). It covers the main view, toolbar, documented windows and tabs, construction controls, keyboard and camera controls, recent messages, and audio cues. The RCT2 manual is the primary behavioral source. OpenRCT2 documentation and community references are secondary evidence and are labeled where used.

Implementation work must use this behavioral description and the cited public references. Do not use original game files, sprites, sounds, music, object data, decompiled material, or copied source code. OpenCoaster art and audio remain newly generated or authored. Exact pixel layouts, message lifetimes, and several sound trigger details are not established by the public sources below; do not invent constants for them.

## Evidence labels

- **Manual verified** — stated in the RCT2 manual or shown by its labeled interface diagrams.
- **Secondary corroboration** — described by OpenRCT2 documentation, community technical references, or player reports; useful but not treated as primary proof of vanilla behavior.
- **Unresolved** — available sources do not establish the exact value or rule.

## Construction interaction details

- **Mouse model:** left-click selects, opens, or places; right-click removes the object/path under the cursor in applicable build contexts. Click-and-hold on dropdown-style controls opens their choices. Track segments can be selected by right-clicking them. [RCT2 manual, pp. 14–15, 27, 31–33, 37](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)
- **Path placement:** choose path type and style; build a connected run by clicking or dragging. Free Path supports elevated bridges and tunnels. Path segments show direction/slope previews; placed sections can be undone with Demolish. [RCT2 manual, pp. 31–33](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)
- **Ride placement:** choose a category tab, choose an attraction, orient/place it, then place the entrance and exit. For custom track, add one valid segment at a time using context-sensitive direction/slope/special-piece controls; placement cost is visible before commit. [RCT2 manual, pp. 34–38](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)
- **Track constraints communicated by UI:** the selector only offers pieces valid for ride/track context; some sections require flat transitions; the ride must be closed to edit. The manual details behavior rather than one universal piece list, because choices depend on ride and preceding track. [RCT2 manual, pp. 37–39, 52–54](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)
- **Scenery placement:** show a footprint/height ghost; reject impossible placements and explain why. Shift adjusts an elevated object's height; Ctrl locks its height to an existing object. [RCT2 manual, pp. 27–30](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)
- **View overlays:** underground view, base-land removal, vertical-face removal, see-through rides/scenery, invisible supports/people, and height marks for land, track, and paths are independently toggleable. Construction below ground automatically turns on underground view. [RCT2 manual, p. 19](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)

## News messages

### Categories and presentation

The original interface uses short notices in the message area and retains them in Recent Messages. The manual explicitly names ride breakdowns, research discoveries, awards, guest complaints, and other park events. The notice color is category-coded and an associated icon can open/center on the subject. Guest tracking can also send that guest's ride/park actions to the message area. The manual does not define an exhaustive category enum, the category-to-color mapping, the ordering policy, or message lifetime. [RCT2 manual, pp. 20–21, 28–29, 46](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf)

## Sound cues

The RCT2 manual documents sound-driver selection, Music on/off, and Low/Medium/High sound quality, but does not give an action-to-sound table. A community mapping of the classic `CSS1.DAT` bank lists the following sound cue families and numeric indices. It is an inventory reference, not proof of the trigger condition or that every sound is used by vanilla RCT2; verify the RCT2 subset in a legally obtained original-game session before tuning audio. ## Prioritized PR-sized work

1. **Classic shell, menus, and window manager** — refine the current toolbar, HUD, message strip, and floating windows against the classic grouping; complete draggable/resizable windows, tab behavior, stacking, close behavior, and the original menu/outcome flow. Match the desktop 800×600 reference composition and responsive scaling rules.
2. **Toolbar, options, shortcuts, and camera** — establish classic group/order; add view filters, minimap entry, Options categories, all default shortcuts, and shortcut reassignment. Implement discrete zoom and clockwise rotation; verify the vanilla zoom ladder before locking scale constants.
3. **Management-window parity** — complete missing tabs and behavior in the existing Park, Finance/Research, Rides/Attractions, Guest, Staff, and Worker windows; add any absent list/detail surfaces and subject navigation.
4. **Build picker and construction workflows** — implement Clear Scenery, Land/Water brush controls, Scenery picker, Footpath/Queue Line modes, category-based ride selection, and context-sensitive track construction with previews/cost/undo.
5. **News behavior parity** — complete categorized notices, subject navigation, and Recent Messages history; verify wording, colors, queue policy, and display durations against the original rather than inferring missing constants.
6. **Audio system** — implement music/sound settings and original-style cue categories using new audio. Confirm cue-to-action mapping through direct behavior observation; do not use extracted game audio.
7. **Mobile interaction pass** — map touch pinch/drag/tap/rotation to the same camera and construction actions, then make all classic windows reachable with usable hit targets at phone widths. Validate a full build/manage/inspect loop on touch hardware or emulation.
