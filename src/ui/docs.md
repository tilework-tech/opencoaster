# Noridoc: User Interface

Path: @/src/ui

### Overview

- Builds the RCT2-style park interface from DOM elements: a top toolbar, floating bevelled windows with per-kind title-bar colours, a lower-left status box (cash, guests, rating bar), a lower-right date/weather box and a news ticker. Layout and behaviour follow [docs/fidelity/ui.md](../../docs/fidelity/ui.md) where implemented; deferred items are listed under Things to Know.
- Displays worker snapshots and timing statistics; authoritative game state remains in the simulation worker.
- Below 700 px width windows become stacked bottom sheets (only the front sheet is expanded; tapping a title collapses/expands), while toolbar actions move under a labeled Actions menu. The mobile menu includes separate clockwise and anticlockwise rotation buttons alongside pause, footpaths, rides, finance, staff, park, and save/load, with touch targets of at least 44 px. Pointer focus preserves a collapsed sheet so its title-bar controls, including close, remain tappable.
- Hosts the game shell: a title screen, an in-game menu (reached from Game options), and a one-time scenario outcome dialog.
- Title and scenario selection use the same bevelled window chrome as the in-game interface. Each category tab shows how many of its scenarios have been won (`Beginner Parks (1/4)`), won scenarios carry a Completed badge in the list, and the preview states the completion date or `Not completed`; the title screen takes a progress callback so it stays independent of storage. New Game groups scenarios under the five manual-listed categories and shows a park illustration, objective and starting details for the selected park; scenario JSON defaults to Beginner Parks unless `category` is set.

### How it fits into the larger codebase

- [src/app/bootstrap](../app/bootstrap/docs.md) creates a [WindowManager](window-manager.ts), the [CoasterPanel](coaster-panel.ts) and the [GameUI](game-ui.ts), and connects `GameUIActions` to [SimClient](../worker/sim-client.ts), camera input, tools, ride setup, and save/load controllers. Placement input becomes simulation commands at the main-thread boundary. [Ride setup](../app/ride-setup/docs.md) uses snapshots and callbacks to advance entrance/exit steps after flat-ride creation and coaster circuit closure. A canvas and SVG overlay shows ride-footprint candidates as accessible targets with placement reasons; the overlay sits below ride windows so setup blocker controls remain interactive. Stall and facility setup uses the adjacent public path as direct service access.
- Windows read `Snapshot` fields only. `Snapshot.economy` (price mode, admission, monthly ledger totals, loan limit) and `Snapshot.research` exist for the Park, Finances and Research windows; `RideInfo.RideX/RideY` locate a ride for clicks on news items and the map, while `RideInfo.DemolitionRefund` supplies the current refund preview in each ride window.
- Award announcements in the park HUD come from `Snapshot.parkNews`, a bounded history published by the worker snapshot; the simulation ledger remains authoritative.
- Snapshots transfer reusable array buffers between the worker and client. Opening a window creates its controller immediately, but it fills from the next animation-frame update so it does not read an older snapshot whose buffers may have been recycled or detached.
- [Hud](hud.ts) shows worker timing and render statistics; it is hidden until View options > Performance overlay is turned on.
- Guest details label hunger and thirst as satisfaction because the stored values use a satiation scale: high means full.
- [title-screen.ts](title-screen.ts), [save-menu.ts](save-menu.ts) and [scenario-dialog.ts](scenario-dialog.ts) are DOM overlays. They call the [app save/load controller](../app/save-load/docs.md), which coordinates [game-saves.ts](../save/game-saves.ts), [slot-store.ts](../save/slot-store.ts) and [SimClient](../worker/sim-client.ts) through callbacks.

### Core Implementation

- [game-ui.ts](game-ui.ts) owns the toolbar ([toolbar.ts](toolbar.ts)), [status-bar.ts](status-bar.ts), news ([news.ts](news.ts) derives messages from successive snapshots: builds, breakdowns, repairs, guest milestones, objective and weather changes) and a map of window controllers. Fresh snapshot messages are filtered by the player's category preferences, recorded in newest-first history, and passed through [messages.ts](messages.ts)'s one-at-a-time ticker queue. Each ticker entry stays for six seconds unless dismissed; the next queued entry then appears. The Recent Messages window can dismiss individual history entries or clear both history and the ticker queue. Options > Messages controls the emitted award, ride, park and guest categories, and those preferences are browser-local settings. The ticker's close control, horizontal touch swipe and Q shortcut dismiss its current entry. Controllers receive snapshots during the regular UI frame update; opening a window creates its controller and DOM, leaving snapshot refresh to that frame loop. At mobile widths, the toolbar's Actions button reveals its labeled menu; desktop keeps the action groups visible. The toolbar includes pause and 1×/2×/4× speed controls, plus a north compass indicator synchronized to camera rotation. Speed buttons pair pixel-art play/fast-forward symbols with visible speed labels. The Game, Sound, Messages, Display and Controls tabs in Options each use distinct pixel-art icons. Opening a construction window (Clear scenery, Land, Water, Scenery, Footpaths, New ride) closes the other construction windows; closing one returns to the Select tool. A new game opens the Park window.
- [windows/land-window.ts](windows/land-window.ts) is the Land window: tool size (+/-), Raise, Lower, Flatten and Smooth, and a switch for single-corner and edge picking. [land-overlay.ts](land-overlay.ts) is the SVG layer over the map showing the selection, the tiles an edit reshapes, an outline of each at its target height, a stem on every corner that moves, and a red tile where an edit is refused.
- [windows/area-windows.ts](windows/area-windows.ts) builds the Clear scenery and Water windows from one spec: a tool size of 1..10 (`LAND_SIZE_RANGE`, an OpenCoaster choice) with −/+ buttons, plus Raise and Lower for Water. The window holds no state beyond these settings and pushes them through `GameUIActions.setClearScenery` / `setWater` to the map tool; opening it selects the `clear` or `water` `ToolMode`, and closing returns to Select. [area-overlay.ts](area-overlay.ts) is their SVG layer (`.area-overlay`): selected owned tiles (`area-sel`, tinted `area-bad` when refused), tiles that would be cleared (`area-hit`), a flat water ghost at the target level for each changed tile (`area-water`, carrying `data-level`), the tile under the pointer (`area-cursor`) and the blocking tile (`area-block`). It redraws only when its inputs change.
- [src/app/input](../app/input/docs.md) connects pointer gestures to camera movement and placement: one-finger drag pans unless a Select-mode person pickup succeeds, pinch zooms on the discrete zoom ladder, two-finger twist rotates, and taps select or issue the active build command. Desktop right-click never shows the browser menu: Select uses the sprite picker and falls back to tile lookup, Patrol removes the patrol tile, Footpaths removes a path, and other tools remove scenery from the tile (see [app input](../app/input/docs.md)). Select-mode hover displays an object name and outline; clicks and touch holds select visible rides, people, the park gate, scenery and path additions. Scenery and path-addition popups show the object's state and expose Remove or Repair actions when applicable. Select-mode mouse drags and touch long-press-then-drag move eligible people; holds without a pickup force selection, while Footpaths holds remove paths. [src/app/tools](../app/tools/docs.md) handles sprite-first selection and tile fallback. Toolbar actions are named Rotate right and Rotate left, with Enter/Z and Shift+Enter/X shown in their tooltips; these actions rotate the camera while keeping the world point at the viewport centre fixed, including the height of nearby terrain, paths and coaster track. The land tool paints while dragging; the path tool lays a footpath run that previews while dragged and is built on release. The canvas uses CSS-pixel coordinates, capped device pixel ratio, and viewport/orientation resize events; the simulation pauses while the tab is hidden.
- Audio settings in Options are owned by [settings.ts](settings.ts) and passed through UI actions to the main-thread [audio engine](../audio/docs.md). Sound volume, music volume, and mute are persisted with the other player settings; audio playback waits for a pointer or keyboard gesture.
- [window-manager.ts](window-manager.ts) and [window-layout.ts](window-layout.ts): draggable windows (title bar), pin, close, tab strip, and z-order. New desktop windows choose a visible corner away from the latest pointer position; pointerdown and pointermove both update that position so a window opened by a click is placed relative to the click target. Each window remembers its last desktop position by id and clamps it to the desktop safe area when reopened or dragged. Placement checks other windows plus the objective strip, HUD and tool-status overlays, so a newly opened window avoids covering the area being worked on where space permits. The safe area leaves room for the top toolbar and the full 68px status bar at the bottom, keeping window content above the status boxes. Mobile bottom sheets use CSS layout instead of desktop positions.
- The Footpaths window has two tabs. Lay line selects tarmac, crazy-paving or dirt surfaces and queue paths, and the tool drags a run; piece by piece adds direction arrows, Level/Up/Down slope, and Build and Remove at the cursor. Surface, queue and remove toggles are shared by both tabs, and every control reports its effect in the status line. The first opening shows a one-line hint, remembered in local storage. Its controller is [path-window.ts](windows/path-window.ts), which drives `FootpathControls` from the path tool; the chosen surface style is stored per path element. The Scenery window selects catalog items by category and shows their catalog costs. Game options > Display keeps gridlines off by default and offers a Gridlines switch; Height labels and Construction marker are disabled with a “Not available yet” tooltip. Shared UI icons use generated pixel-art PNGs at native 16px and 24px sizes. [icons.ts](icons.ts) maps icon IDs to those assets; the sprite generator uses code-authored pixel shapes for icons that need clear silhouettes at native size and mesh rendering for other game-object art.
- [windows/](windows) contains the window controllers for ride selection, ride lists and inspectors, Park, Finances, Research, Map, Staff, guests, recent messages and build tools. The ride inspector has tabs for View, Description, Mechanics, Maintenance record, Ride statistics, Data log, Financial data and Guest data; ticket price is under Financial data. The Park tabs include View, Park rating, Guests, Admission, Park statistics, Objectives and Awards. Each tab in a window uses a distinct icon ID; [tab-icons.test.ts](windows/tab-icons.test.ts) checks the declared tab sets, including the default icon used when a tab omits one. The Park View pane opens [Land Rights](windows/land-rights-window.ts), which reports remaining land and construction-rights offers at their per-tile prices and activates the matching purchase tool; clicking a marked tile requests an individual purchase.
- [guest-window.ts](windows/guest-window.ts) maps thought ids from the selected guest snapshot to display labels, including the lost-guest thought; its Rides tab remains a placeholder because the simulation stores only a guest's last ride and total rides taken, not a full trip list.
- [title-screen.ts](title-screen.ts) formats the selected scenario's objective summary for the preview. Dated objectives show their target and a deadline derived from the objective tick; Have Fun is explicitly open-ended and skips deadline calculation. Monthly-income goals use dedicated labels for monthly ride-ticket income and food/drink profit; other previews enumerate the selected ledger categories, such as admission, ride running and wages. The summary covers the current objective kinds, including ride-count, qualifying-coaster, complete-coaster and best-ride goals.
- [coaster-panel.ts](coaster-panel.ts) is the Ride construction window: shape, slope and bank icon buttons, a Special elements dropdown, drive select, start direction, Build piece / Demolish last piece, Track / Entrance / Exit modes, Test / Open / Close, and the ride readout. Its compact control layout keeps Build piece visible at desktop and phone sizes. Once a circuit closes, it advances into entrance and exit placement before returning to track construction. It opens while the track tool is active; selecting 4× speed while that tool is active is capped to 2×.
- [shortcuts.ts](shortcuts.ts) maps the default keys (Backspace, Shift+Backspace, Esc, Pause/Space, Page Up/Down, Enter, Q, F1-F5, F/D/R/P/G/S/M, Tab); Options > Controls describes the message-dismiss action. [zoom.ts](zoom.ts) holds the four-level discrete zoom ladder used by the toolbar, Page Up/Down, wheel steps and pinch gestures.
- [track-tool.ts](track-tool.ts) is pure logic (`resolvePiece`, `allowedModes`, `previewStatus`, `footprintTiles`, `feedbackMessage`); `resolvePiece` applies the ride allowlist and steep-slope/inversion rules before a piece can appear in the builder. Transport rides allow their generated unbanked track pieces, including the small turns used by normal circuits, and block pieces without atlas coverage. [track-preview.ts](track-preview.ts) draws the flat-ride ghost over the whole rotated footprint (one outline per tile plus the ride's per-tile art slices, with Z or the Rotate ride button turning it); it also draws the placement ghost.
- [icons.ts](icons.ts) maps all UI icon IDs to generated 16px or 24px pixel-art assets. [ui.css](ui.css) holds the interface styles, including pixelated scaling, pressed bevels and disabled grayscale states.

### Things to Know

- The guest roster supports thought, tile, and recent-ride summaries. Individual guest windows show View, Stats, Rides, Cash Info, Recent Thoughts, and Carrying; the simulation records the four most recent ride IDs.
- Staff windows list workers by role and open individual worker details, with role-specific task-order controls and worker statistics. Each worker window opens that person's patrol editor and offers Pick up; the map overlay displays that worker's 4×4-tile patrol blocks while editing. The Staff window's Remove tiles toggle uses shared alternate-action state, and its pressed state is restored when the window is reopened. Guest detail windows also offer Pick up; guests on rides or in queues cannot be moved.
- Footpath removal refunds the piece's cost. It works with the tool toggle, alternate click, context click, or a 900 ms touch hold.
- Desktop windows can be resized. Mobile uses bottom sheets and keeps touch targets at least 44 px. Options are grouped into Game, Sound, Messages, Display, and Controls; sound and music volumes and mute are available, while view-filter effects and shortcut reassignment remain unimplemented. Message categories are award, ride, park and guest, matching the event types currently generated by [news.ts](news.ts); category filtering happens when messages are first observed, before they enter history or the ticker queue. Changing a category later does not remove messages already recorded in history or already queued. Ctrl+S downloads the canvas as a PNG. The UI specification leaves exact message colors unresolved; the six-second ticker lifetime is the current implementation and is not claimed as exact RCT2 behavior.
- Deferred from docs/fidelity/ui.md: view overlays (underground, see-through, and height marks; keys 1, 3-6, 8-0, H, V) remain unavailable; Height labels and Construction marker are disabled with explanatory tooltips. Following guests and workers; guest ride-summary details beyond four recent rides; worker uniform colors; shortcut reassignment; and exact ticker colors remain deferred. Ticker timing is currently six seconds, but is not claimed as exact RCT2 behavior. Enter rotates the view, so building a track piece uses the Build piece button; Delete demolishes the last piece.

- Tool status text reports that a placement was requested. The authoritative outcome arrives in `Snapshot.feedback`, which the panel shows via `feedbackMessage` when `seq` changes, including the research-required result when a locked ride type is submitted. Footpath, Land, Clear scenery and Water rejections also mark the refused tile and show the reason at the cursor (see [app tools](../app/tools/docs.md)); other map-command rejections remain silent.
- The placement preview is a client-side approximation using the snapshot (bounds, ownership via `buildable`, funds); the simulation result is authoritative and may differ.
- Ownership, ride-type rules and funds are enforced by the simulation's track command handler, not by the UI.
- Staff roster identity is matched with stable staff IDs from snapshots; player names travel by ID, while role and position come from the current staff layer. Ground and flower-bed state is carried in per-tile snapshot data, but is not currently drawn by the UI.
- The ride window's main View tab presents a captioned bulldozer Demolish control for every ride, including stalls and coasters. Its tooltip names the action, and confirmation displays the ride name and exact current refund from `RideInfo.DemolitionRefund`. Ride controls request price, open/close, test, demolition, and entrance/exit placement commands; the simulation remains authoritative. Setup blockers offer direct actions to place a boarding point or build a path. Coaster queue connection is derived from queue tiles touching a public path and refreshed by the simulation when paths change.
- `Snapshot` storage is owned by [SimClient](../worker/sim-client.ts) and may be transferred or recycled by the worker protocol. UI event handlers therefore use controller state refreshed from the current frame rather than retaining or exposing a cached snapshot; the ride window caches its locate coordinates from its latest update.
- The ride list keeps row elements keyed by ride id and updates displayed values only when they change, preserving row identity and avoiding repeated DOM writes while simulation values are stable.
- Game speed and pause controls affect the worker through [SimClient](../worker/sim-client.ts); rendering and panel refresh continue on the browser animation frame loop. While paused, construction commands apply immediately and publish updated map/snapshot data without advancing simulation time or running systems. This is an intentional departure from RCT2, whose [manual](https://cdn.akamai.steamstatic.com/steam/apps/285330/manuals/manual.pdf#page=7) says construction is unavailable while paused.
- Speed and the player's pause choice are saved in `localStorage` ([settings.ts](settings.ts)) and restored on the next visit. The worker is also paused while the title screen, the in-game menu or an outcome dialog is open; that pause is not saved.
- Session lifecycle lives in the [app save/load controller](../app/save-load/docs.md). A new game, sandbox start, save load or import replaces the worker's game and clears the session's outcome state. Quitting to title clears the session. Loading a save reads only its header first (`summarizeSave`), so a bad file leaves the current game running.
- Scenario outcome: when a snapshot's scenario status leaves Active, the outcome dialog shows once per game. It offers keep playing (sandbox), the menu, or back to title. The objective strip ([objective.ts](objective.ts)) shows progress and the deadline. Until the first rating refresh (tick 512) the rating reads as pending.
- The park panel shows guest and ride counts, simulation tick and park rating. The finance panel shows cash and loan. Guest details remain a point-in-time selection until another selection replaces or clears them. Person drops target a path or owned dry tile; `setPersonPosition` updates simulation state through the worker command path and is applied while paused without advancing time.
- Ownership visibility is rendered from map ownership flags: unowned ground is shaded, the park edge is fenced, and available parcels use distinct land-sale and construction-rights markings. The shared `expansionOwnership` helper gives the first sellable ring land-sale flags and farther expansion tiles construction-rights flags in both default terrain and scenario terrain generation. This includes Starter Park, whose tree-only definition leaves terrain generation on the default map path. The map overlay and Land Rights window consume the same flags. Construction previews use snapshot buildability, while purchase tools are the route for acquiring flagged tiles.
- Title and menu actions are asynchronous and their failures are shown in the overlay (for example a save that cannot be read, or storage that is unavailable; the title falls back to an in-memory store when IndexedDB cannot be opened, and says so). The scenario preview is newly authored interface art and descriptive scenario metadata, not a capture of original game assets.
- Guest spawning from the toolbar is a development control that sends the existing `spawnGuests` command.
