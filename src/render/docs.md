# Noridoc: Rendering

Path: @/src/render

### Overview

- Turns worker snapshots and map data into the isometric park view without reading simulation state.
- Uses WebGL2 for the primary renderer and Canvas2D as a fallback, with a shared multi-page sprite atlas and a parallel per-pixel height atlas.
- Both renderers resolve occlusion with one per-pixel height model (see "Occlusion model"), checked against an occlusion oracle rather than tuned with per-object painter biases.
- Shares projection and picking rules with the main-thread input layer.

### How it fits into the larger codebase

- [src/main.ts](../main.ts) selects the backend, supplies the current [snapshot](../worker/snapshot.ts) and [map data](../worker/map-data.ts), and requests draws from the browser frame loop.
- [renderer.ts](renderer.ts) defines the renderer boundary, including `setPatrolStaff` for selecting the worker whose patrol mask is rendered. [src/worker](../worker/docs.md) publishes render-ready map and snapshot data; renderers do not access worker-owned simulation state.
- Both backends use [ownership-overlay.ts](ownership-overlay.ts) to draw parcel state above the world canvas from map ownership flags: unowned tiles receive a translucent dark fill and dashed boundary, and sale tiles receive a land or rights marker. Owned land remains unmarked. This overlay is separate from terrain textures and the WebGL ground cache.
- [projection.ts](projection.ts) provides world projection and tile picking for rendering and build input. Picking tests the point against each candidate tile's two projected terrain triangles, using the same four corner heights and rotation-specific split as terrain rendering; this lets input resolve raised and sloped surfaces rather than a flat tile diamond. [create-renderer.ts](create-renderer.ts) handles WebGL setup and Canvas2D fallback.
- Rotation contract: [projection.ts](projection.ts) is the only place that turns a world tile, sub-tile offset and height into screen space under a camera rotation. `worldToScreen` (tile units, height in levels) and its exact inverse `screenToWorld` are the canonical pair; `project` is the fixed-point form for renderer hot paths, `rotatePoint`/`unrotatePoint` and `rotateTile`/`unrotateTile` rotate about the map (a position, never about the object's own origin), `rotateOffset` rotates a displacement, `rotateFootprint` rotates a multi-tile footprint about the map, `rotateDirection` maps a world direction (0 = +x, 1 = +y, 2 = -x, 3 = -y) to the sprite view index (`(d + rotation) & 3`), and `viewDepth` is the rotated `x + y` used by the draw-order key. Both renderers, `pickTile`, the land pick, camera unprojection and the opening camera route through them. [rotation-consistency.test.ts](rotation-consistency.test.ts) asserts, for every rotation and both renderers, that fixture objects land on `worldToScreen` of their tile, that neighbours stay adjacent, that `pickTile` inverts `worldToScreen` on flat and sloped ground, and that rotating four times reproduces the first frame; [e2e/rotation-ownership.spec.ts](../../e2e/rotation-ownership.spec.ts) checks pixel ownership at each anchor. Intentionally non-rotating: the minimap (a fixed overview) and the compass (a label).
- [src/input](../input/docs.md) preserves the world point under zoom and caps device pixel ratio before passing viewport dimensions to the renderer. The canvas is layered with DOM controls and overlays from [index.html](../../index.html).
- [tools/sprites](../../tools/sprites/docs.md) creates generated ride, facility, transport, coaster, path, water, and rock assets and bakes a per-pixel height map for every mesh-rendered sprite; [tools/art](../../tools/art/README.md) packs colour and height pages before development and production builds. [height-encoding.ts](height-encoding.ts) is the encoding contract shared by the packer, both renderers and the oracle.
- [src/dev](../dev/docs.md) hosts the fuzzed-park occlusion fixture, and [e2e/occlusion-oracle.spec.ts](../../e2e/occlusion-oracle.spec.ts) scores both renderers against the oracle in a browser.

### Occlusion model

The projection maps a world point to `sy = 16 * (rx + ry) - 16 * z` (tiles, levels). Along one screen pixel's view ray the height therefore rises 2 levels per tile travelled toward the camera, so every point on that ray has a distinct world height. Per-pixel occlusion reduces to one rule shared by both renderers and the oracle: **at each pixel the highest surface point wins** (larger height = nearer the camera).

```
 tools/sprites raster ──z-buffer + height per pixel──> sprite PNG + .depth.png
          │                                                  │
          v                                                  v
 tools/art pack ───────> colour atlas page  +  height page (R/G = height, A = coverage)
                                   │                │
                       sprite-pages.ts loads both per page
                 ┌─────────────────┴────────────────┐
                 v                                  v
   WebGL2: gl_FragDepth from height      Canvas2D: DepthSurface software composite
                 │                                  │
                 └──────> object-ID capture <───────┘
                                   │
               occlusion-oracle.ts (joint z-buffer) ──> occlusion-metric.ts
```

- **Baked heights.** [tools/sprites/raster.ts](../../tools/sprites/raster.ts) z-buffers each mesh and records the height (levels, relative to the model origin) of the surface seen at every pixel; outline pixels take the height of the nearest-to-camera neighbour they border. [tools/art/pack.ts](../../tools/art/pack.ts) writes an RGBA8 height page per atlas page with the same layout. Sprites without a mesh (prop-sheet art) get an upright card: each opaque row stands `(anchor row - row) / 16` levels above the anchor.
- **Pixel height** = sprite anchor height (world height of its ground pivot, levels) + baked height × (drawn height / frame height). Ground, cliffs and banks are meshes whose vertex heights interpolate.
- **Shared sampling.** Both renderers and the oracle sample the nearest texel with a half-texel inset, treat alpha below one half as uncovered, and let the later draw win an exact height tie.
- **Draw-order key.** [depth-key.ts](depth-key.ts) exports only `anchorKey` (`2 * (rx + ry) - height` at the ground pivot) and `rotatedPositionSum`. The key no longer decides occlusion: it orders the translucent pass back to front and settles exact ties, and it carries no per-object bias.
- **Placement, not bias.** Fixes that fell out of the model are geometric: people (guests and staff), litter and path props stand on the path mesh's walking surface (`PATH_SURFACE_Z` in [ground-anchor.ts](ground-anchor.ts)) so the slab never covers their feet, and flowerbed soil is lifted one screen pixel above the terrain ([tools/sprites/models/flower-bed.ts](../../tools/sprites/models/flower-bed.ts)) because coplanar soil z-fought with the ground.
- **Oracle.** [occlusion-oracle.ts](occlusion-oracle.ts) composites placed sprites (anchor height + baked height) and ground/water triangles from [oracle-terrain.ts](oracle-terrain.ts) into an object-ID image; [occlusion-oracle.test.ts](occlusion-oracle.test.ts) proves this equals a joint z-buffer over the placed meshes. [occlusion-metric.ts](occlusion-metric.ts) scores a renderer's ID image against it: the share of object pixels mismatched, coverage-only mismatches (renderer shows a kind that does not cover the pixel), and per object-kind pair (`oracle>rendered`) mismatches with their contested pixel counts. [object-kinds.ts](object-kinds.ts) maps atlas keys to kinds and reserves shared ids for ground and water.

### Core Implementation

- [sprite-pages.ts](sprite-pages.ts) owns the manifest and page images shared by both renderers. World and people categories load at startup; lazy categories load when a sprite key is resolved or a UI surface calls `requestCategory`. Until a category is ready, callers can draw their procedural fallback.
- Object-picking masks are extracted from the same loaded atlas pages and cached per atlas instance, sprite frame and atlas version. The shared [object-picking.ts](../input/object-picking.ts) builds ride-cell targets from `RideCellScene`, so each visible slice of a sliced flat ride can be hit-tested while Select-mode hover groups its body targets with its entrance and exit. Guest target frames use the camera-rotated walking direction. Target geometry follows the projected sprite anchor and shared sizing helpers, so input hit bounds use the same camera transform and object placement contract as the rendered scene. Each renderer caches its target list by snapshot publication revision, camera, viewport and atlas version; the revision invalidates targets after paused state changes even when the simulation tick and pooled buffer identity repeat.
- [webgl2-renderer.ts](webgl2-renderer.ts) uploads each loaded atlas page as a nearest-filtered texture without mipmaps, and samples each sprite from half a texel inside its manifest frame. Together with the transparent gutters added by [tools/art](../../tools/art/README.md), this keeps adjacent atlas cells out of sprite samples. It batches native sprite instances in key order. A draw binds at most eight page textures (units 0-7) plus the matching height pages (`uHeights0..7`, units 8-15); when consecutive instances require more pages, the batch is split at that boundary and subsequent draws retain the original instance order. Height pages are uploaded byte-exact through a canvas, because WebGL ignores `UNPACK_FLIP_Y` for ImageBitmap sources; pages without heights bind a coverage-free fallback so their sprites stand as upright cards. A small procedural atlas supplies fallback sprites. The DOM toolbar's separate UI sheet is outside the world atlas.
- [world-art.ts](world-art.ts) derives ride, facility, entrance/exit hut, path, water, terrain, scenery, path-addition, and litter keys from snapshot and map values. `shrubSpriteName` picks one of four generated shrub variants from the tile coordinates plus the camera view, shared by both renderers and the placement preview. `wallSpriteName` combines wall item, stored tile edge, terrain slope mask and camera view so edge walls render correctly in every view and on sloped terrain. Flat rides with a footprint are drawn as one slice per footprint tile (`rideCellSpriteKey`, view = camera rotation + ride orientation; `rideHutFacingForFootprint` faces entrance and exit huts toward the footprint tile they touch); stalls and other single-tile rides select one of four views. All use the idle frame or tick-driven operating animation; facilities and station huts select direction-facing variants. The park entrance uses the generated gate sprite. Rain shelters and vandalised benches, bins, and lamps select generated four-view sprites; regular lamps, flower beds, and gardens keep using prepared prop-sheet sprites.
- [ground-anchor.ts](ground-anchor.ts) is the shared placement contract for both renderers: it supplies ground boxes for scenery, native-size flower-bed frames, and rain shelters, and the path walking surface `PATH_SURFACE_Z`, path-addition placement (`pathAdditionPlacements`: one copy per open, unconnected edge, offset 96 world units from the tile centre and so inside the tile; a crossroads gets none, except lamps, which stand as four corner posts), path-addition edge and ramp elevations, rotation-dependent tile-centre elevations for sloped scenery and flower beds, and the horizontal sprite-anchor shift used by WebGL2. Flowerbed ground elevation is the average height along the diagonal shared by the two terrain triangles for the camera rotation, plus the small ground-surface offset; it anchors placed and ambient beds and the placement preview.
- [coaster-art.ts](coaster-art.ts) maps tracked rides to coaster, water, or transport families and constructs track-cell and vehicle keys. [coaster-scene.ts](coaster-scene.ts) turns snapshot track and car layers into a reusable key-ordered list; track-piece cells follow piece direction and camera rotation, coaster supports stack to the ground beneath the in-cell track sample nearest the tile centre (`supportOffset`, so a column stands under the rails even where a turn hugs a tile edge), and cars or boats use per-car poses. Car draw keys use the continuous projected world position through `viewDepth`, rather than snapping each vehicle to a tile centre. Water boat keys include each car's packed passenger count to select empty or loaded sprites; the meshes show up to four passenger figures for Log Flume boats and seven for River Rapids boats. Log Flume and River Rapids therefore render track and boats through this scene; their older static ride dioramas remain generated art but are no longer the ride's runtime representation.
- Generated guest sprites use the `people/guest-walk#N` frames from [tools/sprites](../../tools/sprites/docs.md), indexed by guest tint, heading, and walking pose. Both renderers resolve them from the eager `people` atlas; [GUEST_BOX](sprite-layout.ts) supplies the 20×24-pixel visibility and fallback bounds. Model-generated people frames render at native size. Guests in the `Riding` state (`isRidingGuestRow`) are skipped by both renderers: they are drawn by their ride instead. [coaster-scene.ts](coaster-scene.ts) seats up to four `people/rider-seated` figures along each coaster, mouse, railway and monorail car from the car's packed passenger count; Log Flume and River Rapids boats and chairlift chairs already bake riders into their car art, and flat and enclosed rides show none, so a rider is never also a walking sprite. Riders reappear as walkers at the exit when the guest leaves `Riding`. Generated staff sprites encode uniform role and cardinal facing in their keys and provide four walking poses; the renderers combine staff heading with camera rotation and cycle all four poses from simulation ticks. Canvas2D draws ambient trees, flower beds and placed scenery from the atlas using the catalog or shared boxes supplied by [sprite-layout.ts](sprite-layout.ts) and [ground-anchor.ts](ground-anchor.ts), matching WebGL2 sizing.
- WebGL2 and [canvas2d-renderer.ts](canvas2d-renderer.ts) consume the generated art. Canvas2D resolves the same page store through [canvas-atlas.ts](canvas-atlas.ts), draws sprites at manifest frame size and anchor with image smoothing disabled, and keeps procedural terrain and fallback drawing. The affine Canvas2D cliff-texture path also disables smoothing while mapping atlas art onto terrain faces. Flowerbeds use their own tile's projected centre and terrain-derived elevation in both backends; native frame sizing and the manifest ground pivot keep their rendered footprint aligned with that tile. Their generated soil rests one pixel above the terrain, so the bed always wins against the ground under it. Litter uses a compact, flat generated sprite at its projected ground point; both backends use the shared 6×3-pixel target size in [world-art.ts](world-art.ts), keeping its footprint close to the path surface, with a small procedural fallback in Canvas2D. Both renderers use `pathAdditionGroundZ` (which includes the path walking surface) for flat and ramp path additions, with ramp props anchored at the path centre elevation; `pathAdditionBox` gives intact and vandalised variants of a prop the same rendered dimensions: 22×18 for benches, 8×11 for bins and 8×25 for lamps (the sprite bounds; the drawn size comes from the native sprite, sized against a guest in [path-additions.ts](../../tools/sprites/models/path-additions.ts): bench about 0.6, bin 0.45 and lamp 1.4 guest heights). Benches, bins, and lamps are derived from path connection flags and rendered at each unconnected edge, with the sim still storing one addition per tile; each faces the path, rotates with the edge and camera, and follows the ramp height at that edge. The same helper output drives the translucent path-addition preview, so preview and completed props share position and sizing without adding save data. `PATH_ADDITION_BROKEN` selects the vandalised furniture variants. [src/ui/track-preview.ts](../ui/track-preview.ts) uses generated ride keys for build-placement ghosts.
- The [development art-coverage report](../../docs/art/coverage.md) exposes the sprite inventory and both backend paths; the Vite-only `/__art-coverage` endpoint renders it live. [tools/sprites/coverage.test.ts](../../tools/sprites/coverage.test.ts) verifies generated and prepared sprite-key availability for catalog entries, rejects ride rows with empty or missing keys, and checks fallback status when required art is missing. [canvas2d-renderer.test.ts](canvas2d-renderer.test.ts) also exercises the Canvas2D atlas path by drawing a rain shelter on a path tile.
- [ride-scene.ts](ride-scene.ts) builds the slice draw list of flat rides from `RideInfo.RideX/RideY/Dir/BaseLevel`: each slice is drawn at its tile's centre at z = `BaseLevel * Z_STEP` with that tile's draw key; per-pixel height lets guests, scenery and neighbouring rides interleave with the slices in every camera rotation. The same scene supplies per-slice pick targets, with ride identity retained so the input overlay can outline the complete flat ride when any cell is hovered. Slices missing from the atlas are skipped.
- [src/render/coaster-scene.ts](coaster-scene.ts) marks rides whose coaster, water, or transport sprites are available so procedural track and vehicle markers are omitted for those rides. If the corresponding atlas art is not available, the renderer retains the procedural markers.
- Ground cache: the WebGL renderer paints terrain, boundary cliff faces and flat path fill into 512×512 world-pixel textures on demand by reusing the instanced sprite shader and its page-texture runs at zoom 1 ([ground-chunks.ts](ground-chunks.ts) provides `chunkRange` and the LRU cache). It draws an earth cliff face on every tile edge that turns toward the viewer and is higher than the neighbouring tile's matching edge (`terrainNeighborEdgeBase`, `terrainEdgeFacesViewer` in [terrain-geometry.ts](terrain-geometry.ts)), and at the map border down to sea level. Each chunk has a second colour attachment (MRT) holding the encoded height of every pixel; when chunks are drawn to the screen that height is written as depth (background is far), so the cached ground occludes like live geometry. Sprites painted into the cache (path-fill underlay) record their anchor height there. Chunk bounds for every tile include their extrusion to the ground plane; a changed tile also invalidates its adjacent tiles' chunks because a shared face's height depends on both tiles. Chunks are keyed by coordinate and cleared on rotation, gridline toggle, or when the `world` atlas category finishes loading; a new `MapData` drops only chunks touching tiles whose height, surface, slope or water level changed. Ownership is drawn in its own overlay and does not invalidate ground chunks. The ownership overlay repaints only when the `MapData` identity or camera position, zoom, rotation, viewport size, or device-pixel ratio changes.
- WebGL2 depth pass: world sprites draw with `DEPTH_TEST` (`LEQUAL`, so the later draw wins ties) and write `gl_FragDepth = 0.5 - height * DEPTH_PER_LEVEL`, discarding fragments with alpha below one half. Opaque instances draw first; water, patrol overlays and placement previews form a translucent pass drawn afterwards with `depthMask(false)` (still depth tested). `uploadInPainterOrder` partitions instances into the two passes, each keeping key order, and builds texture runs per pass. There is no terrain occluder redraw; the ground cache's height attachment does that work.
- Object-ID capture: `captureObjectIds` on either renderer draws the same frame and returns an object id per backing pixel, the placed atlas sprites, their kinds and pages. WebGL2 renders into an RGBA8 + DEPTH24 framebuffer with blending off and previews and patrol overlays discarded; Canvas2D records ids inside its depth composite.
- Canvas2D depth composite: ground (terrain fill and textures, water, cliff faces, raised-tile redraws) is painted as before; ground queue items are flagged `ground` and flushed first, ordered only among themselves. Then [depth-surface.ts](depth-surface.ts) wraps the 2D context in a Proxy. During `compose`, every atlas `drawImage` is software depth-composited by [depth-composite.ts](depth-composite.ts) into the frame's ImageData at the current anchor height, set by the renderer's `anchor()` helper when it projects a sprite's ground pivot; any non-atlas drawing (procedural fallbacks, placement previews drawn through the tint canvas) is deferred and replayed on top after `putImageData`. Ground heights come from span-rasterising the oracle terrain triangles and are cached per view (map revision, camera, size). The canvas is created `willReadFrequently`. When the context cannot be read back (unit-test fakes), the renderer falls back to drawing in key order.
- Patrol rendering reads the selected worker's allocated 4×4-block bit mask from the snapshot. Canvas2D fills and outlines each marked tile during terrain traversal using its four terrain corner heights; WebGL2 emits corresponding corner-height tile meshes into the translucent pass, depth tested against the ground and world sprites. The selected area uses a translucent blue fill and pale blue edge; `setPatrolPreview` supplies the hovered 4×4 block and whether the action adds or removes it, rendered as a pale dashed white preview or a red removal preview. Passing `null` to `setPatrolStaff` hides the in-world patrol surface and its preview.
- Queue rails along the two camera-facing edges of a flat queue piece remain separate sprites (`queueRailSprites`), in both renderers and in path ghosts; they share the piece's draw key, and per-pixel height places queuing guests between the front and rear rails in every rotation.
- Sprite ordering uses [painter-order.ts](painter-order.ts) (stable counting sort) and `bufferSubData` uploads. [adaptive-resolution.ts](adaptive-resolution.ts) turns frame times into a backing-buffer scale; [src/app/bootstrap](../app/bootstrap/index.ts) applies it to the device pixel ratio passed to `Renderer.resize` and throttles HUD and panel DOM updates.

### Things to Know

- Atlas category names follow key prefixes in [tools/art/categories.ts](../../tools/art/categories.ts): `flat-rides`, `stalls`, `transport`, `track-<style>`, `vehicles`, `coaster-<family>`, and `water`. Coaster and water ride families have lazy pages; first use requests the matching category. WebGL's eight-page draw limit is handled by consecutive ordered batches, preserving key order even when a view uses many ride categories.
- `Renderer.objectTargets` returns the cached alpha-mask pick list (`pickObject` searches it); targets carry their atlas key, ground-anchor offset and source rectangle so UI overlays can outline or redraw them. `setHeldPerson` makes both renderers skip one guest or staff row while the player holds them; the app tools redraw that target at its walking size with a dark outline and a zoom-scaled ground shadow.
- Native sprites are positioned with manifest frame dimensions and anchor metadata. The manifest anchor is the sprite's ground pivot. Atlas packing trims transparent borders asymmetrically, so WebGL2 applies vertical anchor compensation and [ground-anchor.ts](ground-anchor.ts)'s horizontal shift to preserve that pivot after trim; Canvas2D applies the corresponding shift for native and boxed sprites. Boxed sprites and their ghosts use the same unrounded destination-rectangle calculation, so preview sizing and anchor placement follow the placed art. Multi-tile coaster, transport track and flat rides are represented as tile-sized cells, each with its own anchor height and draw key.
- Terrain uses generated material surfaces and directional cliff sprites. Both renderers draw cliff faces for every surface wherever a viewer-facing tile edge is higher than the neighbour's matching edge, and at the map border; the face texture is an opaque earth patch cut from the generated cube sprite by [cliff-wall.ts](../../tools/art/cliff-wall.ts). Both use `terrainEdgeFace` from [terrain-geometry.ts](terrain-geometry.ts) and rotate the directional cliff key with the camera. Canvas2D projects and clips the sprite onto the face quadrilateral, with a shaded fill when the atlas art is unavailable. Generated rock surface and cliff textures replace the prepared source rock keys. WebGL water is a planar surface below the recorded water level, lowered by `WATER_BANK.surfaceInset`; it is clipped against the same two terrain triangles per tile that the view's terrain quad uses (`terrainMeshTriangles`), and the fragment shader shades it by depth. Canvas2D clips against those same triangles so alternating corner heights keep separate submerged regions. Both renderers draw earthy bank faces from shared shoreline segments; in WebGL2 they are opaque ground meshes and the water plane is translucent, so per-pixel height keeps a tile's water from covering its own walls. Both renderers select animation frames from the simulation tick.
- Footpath placement previews arrive through `Renderer.setGhosts` as `PathPieceGhost` entries. Both renderers draw them with the same sprite and anchor as a built piece (`pathElementSprite`), translucent; refused tiles are tinted red. WebGL2 sends a per-instance ghost mode (accepted or refused) and draws ghosts in the translucent pass, depth tested but writing no depth; Canvas2D queues them per tile and draws them through `drawGhostSprite`, which blits from a tint canvas rather than the atlas, so the depth surface defers them and replays them on top of the composited frame.
- Ride, scenery, flowerbed, and path-addition placement previews arrive through `Renderer.setSpriteGhosts` as `SpriteGhost` entries. They are drawn translucent at the anchor of the built piece and tinted red when refused; WebGL2 height tests them without letting them hide anything, while Canvas2D draws them over the composited frame. Ordinary scenery ghosts carry the catalog box and slope- and camera-view-dependent tile-centre ground pivot; wall ghosts instead use the selected edge sprite and tile base elevation so the preview aligns with the boundary. Flowerbed ghosts carry the native-frame ground pivot and shared visibility box computed from the same tile slope and camera rotation as placed beds. Path-addition ghosts carry their open-edge world offset, edge ground level, rendered box, and optional source tile coordinates. WebGL2 appends these ghosts to its translucent pass, while Canvas2D groups them by source tile when supplied (falling back to their rendered tile coordinates) and enqueues them alongside completed objects; both backends apply the sprite's manifest anchor and packed-trim compensation.
- Placed scenery elements (`SmallScenery` from `map-data.ts`, including scenario trees) are drawn with their catalog sprite (`trees/...`, `scenery/...`). Both renderers use [ground-anchor.ts](ground-anchor.ts) to anchor them at the rendered tile-centre surface elevation, computed from the triangulated terrain and camera rotation, and to use the catalog's shared scenery box. The scenery placement tool supplies the tile slope and catalog item to the same ground-anchor contract, so the translucent preview uses the placed object's box, ground pivot and sprite anchor. Flowerbed frames match the tile's corner heights and terrain triangle split, and draw at native frame size with their anchor on their own projected tile centre. The same pivot and slope/view-specific sprite key are sent to the placement ghost. Source-sheet trees are rotation-invariant single-frame sprites; model-generated palm and cactus sprites select a camera-facing view so their asymmetric fronds and arms rotate with the park.
- Wall scenery is a separate boundary placement contract: both renderers use the saved edge flag and `wallSpriteName`, draw the sprite at its native frame size (placed walls and ghosts alike), anchor the sprite at the tile base, and preserve the source tile for its draw key. Their assets include both edge orientations, all terrain corner masks, and all camera views, allowing continuous fence lines to follow the endpoint heights of sloped edges.
- Ambient trees are deterministic rendering decorations, not simulation entities or saved objects. Shared [world-art.ts](world-art.ts) selection keeps Canvas2D and WebGL2 aligned, selecting broadleaf/conifer variants on grass and palms or cacti on sand. Weather shading and rain are DOM overlays; worker snapshots provide the weather state.
- Ownership overlay coordinates use the same isometric projection, camera rotation, zoom, and CSS-pixel viewport as the map. It consumes map ownership, base height, and corner slope data, so the worker map message must be refreshed when these change. Non-owned tiles receive a dark translucent fill; the edge of owned territory gets a rail-and-post fence whose endpoints follow the individual terrain corner heights, while sale borders use gold dashes for land and blue dots for construction rights. Tiles offered for both show the combined gold treatment. The overlay is separate from ground chunks, so purchase changes repaint the overlay without invalidating terrain textures.
- [src/sim](../sim/core/docs.md) owns simulation behavior and placement validation. [smoke/docs.md](../../smoke/docs.md) describes browser-level rendering and build-control checks.
- For Canvas2D, the oracle check validates plumbing and placement capture (ids, anchors, frames), not ordering, because the depth composite uses the oracle's own algorithm. The WebGL2 score is the independent check of ordering.
- Height values are 16-bit at 1/256 level, offset by 32768, with alpha as coverage ([height-encoding.ts](height-encoding.ts)). Height pages hold packed integers, so they are decoded without colour-space conversion or alpha premultiplication everywhere they are loaded.
- A person under a bridge deck, a person behind a raised tile, and a guest between queue rails are all ordinary per-pixel cases; no per-object depth exception exists, and adding one would diverge from the oracle.
- Terrain-reading aids: `terrainLightFactor` lights slopes from a fixed screen side (WebGL2 shader multiplier; Canvas2D white/black overlay). With gridlines on, `terrainContourViewEdges` flags level tile edges where the ground changes inclination or steps; WebGL2 packs the edge mask into the per-instance gridline float, Canvas2D strokes the edges. [height-marks.ts](height-marks.ts) computes visible height-number placements, drawn by [src/app/terrain-aids.ts](../app/terrain-aids.ts).
