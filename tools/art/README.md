# World art pipeline

The art pipeline keeps OpenCoaster independent of original game files and copied code. The committed source sheets under [source/](source/), the saved generation prompts in [prompts/](prompts/), and the generators are authoritative. `public/sprites/` is generated output and is ignored by Git; do not commit its pages, manifest, per-sprite PNGs, or metadata. Normal development and production builds consume the saved artwork and do not call an image-generation service.

## Preparation

[prepare.ts](prepare.ts) clears and recreates `public/sprites/`, then crops, trims transparent padding, defringes transparent-edge RGB, resizes with nearest-neighbour sampling, and quantizes images to a deterministic 64-colour palette. Per-sprite JSON records frame rectangles, bottom-centre anchors, and tile footprints. [pack.ts](pack.ts) validates that metadata, trims the transparent borders of `native` sprites, assigns every sprite to a category from its key prefix ([categories.ts](categories.ts)), and packs each category's frames with MaxRects ([maxrects.ts](maxrects.ts)) into transparent PNG pages of at most 2048x2048 pixels under `public/sprites/atlas/<category>-<n>.png`. Every frame reserves a two-pixel transparent gutter, and the manifest frame coordinates point to the sprite content inside that gutter. Beside each colour page it writes a height page (`<category>-<n>.depth.png`) with the identical layout: a frame's baked height map from [tools/sprites](../sprites/docs.md) when its source has a `.depth.png`, otherwise an upright card through the frame's trimmed anchor (each opaque row stands `(anchor row - row) / 16` levels high). Heights use the encoding in [src/render/height-encoding.ts](../../src/render/height-encoding.ts) and drive per-pixel occlusion in both renderers ([src/render/docs.md](../../src/render/docs.md), "Occlusion model"); source `.depth.png` files are never packed as sprites themselves. `manifest.json` lists the pages (`file`, `depthFile`, size, category), the categories (`lazy` flag and page indices) and, for each sprite, its category and its frames as `{ page, x, y, width, height }`. Packing is deterministic and fails when a sprite plus its gutter exceeds the page size. The standalone 16px and 24px UI icon PNGs are generated under `public/sprites/ui-icons/` and excluded from the atlas; the DOM loads each native-size image directly.

Categories group pages that load together: eager ones (`world`, `people`) load at start, lazy ones (flat rides, stalls, each coaster family, vehicles) load when first needed. To add a category, append a rule to `ATLAS_CATEGORIES` in [categories.ts](categories.ts); no packer or renderer change is needed. The service worker precaches everything in `public/`, so every page is available offline.

The terrain sheet supplies distinct source cells for the 16 combinations of the map's 4-bit corner slope mask, plus directional cliff faces, for grass, sand, dirt, and rock. Preparation crops and cleans each authored cell; it does not rotate or reflection-cycle a smaller set of slope drawings. After preparation, [tools/sprites](../sprites/docs.md) overwrites the rock surface key with a generated textured tile and adds four generated directional rock cliff-face keys. The renderer projects tile corners for continuous terrain tops, draws directional cliff faces at map boundaries, and draws exposed interior faces on rock tiles. The map encodes one-level corner differences and has no separate steep-slope encoding.

Footpaths, the water texture, and the palm and cactus trees are not prepared from source sheets: [tools/sprites](../sprites/docs.md) renders them from 3D models into the same output directory (after the sheets are prepared, within the same `art:prepare` run), and the packer treats them like any other sprite. The props sheet is cut by [prop-cutter.ts](prop-cutter.ts): props are found as connected groups of opaque pixels (with a few pixels of gap tolerance) and each group goes to the sprite whose grid cell holds its centroid, so a trunk that overhangs its nominal cell stays whole and the overhang of the prop above never lands in the next cell; isolated specks are dropped. The props sheet supplies ambient trees, placeable scenery, and other park props (queue rails are part of the generated queue path pieces, not a prop drawn on top); the saved prompt and source image remain the reproducible inputs. Source sheets are newly generated artwork and must not be replaced with original game sprites.

People art has two inputs. Guest figures and staff walking sprites are generated from the clean-room 3D models in [tools/sprites](../sprites/docs.md); they are rendered into native sprite frames during `art:prepare` and packed into the eager `people` category. The committed [staff-costumes.png](source/staff-costumes.png) sheet is still processed by [process-sprites.ts](process-sprites.ts) as supplementary costume art. It does not define the runtime guest walking sprites. The older guest walking source sheet and prompt are not part of the active generation path.

Run `pnpm art:prepare` to regenerate sprite PNG/JSON inputs, then `pnpm art:pack` to build the atlas pages and manifest. `prepare.ts` also runs the model-based renderer in [tools/sprites](../sprites/docs.md). The `predev` and `prebuild` package hooks run both steps automatically, so a fresh checkout prepares the assets before `pnpm dev` or `pnpm build`. The smoke and e2e Playwright configs start their server with `pnpm dev`, so they use the same preparation hook; `pnpm smoke:subpath` builds first. CI and the GitHub Pages workflow invoke `pnpm build`, which prepares assets through `prebuild` before bundling. The Pages workflow's additional `vite build --base /opencoaster/` runs after that generated output exists.

Vite's dev-server watcher ignores `public/sprites/**`; regenerating the large tree therefore does not consume the Linux file-watcher limit or trigger app reloads. The browser still serves and bundles the generated files normally. UI icon sources and their mesh-rendered object models live in [tools/sprites/ui-icons.ts](../sprites/ui-icons.ts). The `art:prepare` lifecycle hook regenerates both icon sizes alongside the world sprites. Make art changes in committed sources, prompts, or generators, then let the package lifecycle hooks recreate the ignored output. Nothing under `tools/` keeps generated sprites; `tools/sprites/.build/` is ignored scratch.
