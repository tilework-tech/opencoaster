# World art pipeline

The art pipeline keeps OpenCoaster independent of original game files and copied code. The committed source sheets under [source/](source/), the saved generation prompts in [prompts/](prompts/), and the generators are authoritative. `public/sprites/` is generated output and is ignored by Git; do not commit its pages, manifest, per-sprite PNGs, or metadata. Normal development and production builds consume the saved artwork and do not call an image-generation service.

## Preparation

[prepare.ts](prepare.ts) clears and recreates `public/sprites/`, then crops, trims transparent padding, defringes transparent-edge RGB, resizes with nearest-neighbour sampling, and quantizes images to a deterministic 64-colour palette. Per-sprite JSON records frame rectangles, bottom-centre anchors, and tile footprints. [pack.ts](pack.ts) validates that metadata, trims the transparent borders of `native` sprites, assigns every sprite to a category from its key prefix ([categories.ts](categories.ts)), and packs each category's frames with MaxRects ([maxrects.ts](maxrects.ts)) into transparent PNG pages of at most 2048x2048 pixels under `public/sprites/atlas/<category>-<n>.png`. `manifest.json` lists the pages (`file`, size, category), the categories (`lazy` flag and page indices) and, for each sprite, its category and its frames as `{ page, x, y, width, height }`. Packing is deterministic and fails when a single sprite exceeds the page size. The standalone UI icon sheet is written to `public/sprites/ui/` and excluded from the atlas; the DOM loads it directly.

Categories group pages that load together: eager ones (`world`, `people`) load at start, lazy ones (flat rides, stalls, each coaster family, vehicles) load when first needed. To add a category, append a rule to `ATLAS_CATEGORIES` in [categories.ts](categories.ts); no packer or renderer change is needed. The service worker precaches everything in `public/`, so every page is available offline.

The terrain sheet supplies distinct source cells for the 16 combinations of the map's 4-bit corner slope mask, plus directional cliff faces, for grass, sand, dirt, and rock. Preparation crops and cleans each authored cell; it does not rotate or reflection-cycle a smaller set of slope drawings. After preparation, [tools/sprites](../sprites/docs.md) overwrites the rock surface key with a generated textured tile and adds four generated directional rock cliff-face keys. The renderer projects tile corners for continuous terrain tops, draws directional cliff faces at map boundaries, and draws exposed interior faces on rock tiles. The map encodes one-level corner differences and has no separate steep-slope encoding.

Footpaths, the water texture, and the palm and cactus trees are not prepared from source sheets: [tools/sprites](../sprites/docs.md) renders them from 3D models into the same output directory (after the sheets are prepared, within the same `art:prepare` run), and the packer treats them like any other sprite. The props sheet supplies ambient trees, placeable scenery, queue rails, and other park props; the saved prompt and source image remain the reproducible inputs. Source sheets are newly generated artwork and must not be replaced with original game sprites.

The guest walking sheet ([guest-walk.png](source/guest-walk.png)) and staff costume sheet ([staff-costumes.png](source/staff-costumes.png)) are processed by [process-sprites.ts](process-sprites.ts) (`pnpm art:characters`, run by `pnpm art:prepare` after the sheets above) into `public/sprites/people/`, which the packer places in the eager `people` category. Cells are 32x32 and the figure fills at most 75% of the cell width and 72% of its height with its feet one pixel above the cell bottom, so cell size sets the on-screen figure size; the renderers draw each cell 1:1. Guest sheets are expanded into eight palette variants. Prompts: [guest-walk.md](prompts/guest-walk.md), [staff-costumes.md](prompts/staff-costumes.md).

Run `pnpm art:prepare` to regenerate sprite PNG/JSON inputs, then `pnpm art:pack` to build the atlas pages and manifest. `prepare.ts` also runs the model-based renderer in [tools/sprites](../sprites/docs.md). The `predev` and `prebuild` package hooks run both steps automatically, so a fresh checkout prepares the assets before `pnpm dev` or `pnpm build`. The smoke and e2e Playwright configs start their server with `pnpm dev`, so they use the same preparation hook; `pnpm smoke:subpath` builds first. CI and the GitHub Pages workflow invoke `pnpm build`, which prepares assets through `prebuild` before bundling. The Pages workflow's additional `vite build --base /opencoaster/` runs after that generated output exists.

Vite's dev-server watcher ignores `public/sprites/**`; regenerating the large tree therefore does not consume the Linux file-watcher limit or trigger app reloads. The browser still serves and bundles the generated files normally. Make art changes in committed sources, prompts, or generators, then let the package lifecycle hooks recreate the ignored output.
