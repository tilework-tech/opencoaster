# Noridoc: Scenario Preview Generation

Path: @/tools/scenario-previews

### Overview

- Generates the static map thumbnails used by New Game from the scenario JSON catalog.
- Writes each map as a native-size PNG and a nearest-neighbour 2× PNG under `public/scenario-previews/`, with a manifest of dimensions, renderer version and source hashes.

### How it fits into the larger codebase

- [package.json](../../package.json) runs the generator before the Vite development server and production build, so the title screen uses ready-to-load static images rather than constructing previews when it opens.
- [generate.ts](generate.ts) uses [scenario-file.ts](../../src/sim/scenario/scenario-file.ts) and [scenario-layout.ts](../../src/sim/scenario/scenario-layout.ts), the same validation and map-preparation path used to start a scenario. It then calls [scenario-preview.ts](../../src/sim/scenario/scenario-preview.ts) to rasterize the resulting `World`.
- [title-screen.ts](../../src/ui/title-screen.ts) reads the generated images from the public asset directory, selecting the 2× file through `srcset` when the display density allows it.
- [scenario-preview-assets.test.ts](../../src/sim/scenario/scenario-preview-assets.test.ts) compares the catalog with the checked-in manifest and image files, tying those assets to their source JSON and renderer version.

### Core Implementation

- The generator walks scenario JSON files in sorted order, parses each definition, initializes a `World` with the scenario's seed and dimensions, and calls `prepareScenario` before rendering. This includes generated terrain, ownership, entrance, scenery and any configured prebuilt rides.
- The renderer returns RGBA pixels with one pixel for each map tile. `sharp` encodes that buffer as PNG and produces the 2× image with nearest-neighbour resampling to preserve tile-sized pixel art.
- The manifest records a SHA-256 hash of each source JSON, output filenames and map dimensions. `writeIfChanged` preserves file timestamps when generated bytes match existing output.

### Things to Know

- Renderer output is versioned separately from scenario data. Bump `SCENARIO_PREVIEW_RENDERER_VERSION` in [scenario-preview.ts](../../src/sim/scenario/scenario-preview.ts) when changing the rendering rules so the asset test requires regeneration.
- The asset test checks source hashes, catalog coverage, dimensions and exact 2× pixel replication. Changes to scenario maps are therefore detected even when the output files still exist.
- Generation errors from parsing, preparing a world or encoding an image fail the invoking development or build command; output is static and does not depend on sprite loading at runtime.
